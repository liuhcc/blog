## 案例目标

智能点餐场景需要回答菜品咨询、进行推荐、查询菜单并校验配送范围。它是一个典型的多工具业务助手：模型负责理解请求和组织答复，业务服务负责执行确定性查询与校验。

## 推荐分层

- API 层：使用 FastAPI 定义聊天、配送和菜单等接口及输入输出模型。
- Agent 层：负责意图识别、工具选择和流程路由。
- 工具层：封装地图、菜单数据、向量检索和模型调用等能力。
- 服务层：处理业务规则，例如配送距离和订单状态。
- 提示词层：按通用咨询与菜单咨询等场景维护提示词模板。

## 关键原则

配送范围、菜品价格和订单状态必须由后端工具确认，不能由模型猜测。所有外部 API、数据库和向量服务的连接信息都应通过私有环境配置注入；接口需要返回可识别的失败状态，而不是把底层异常直接暴露给用户。

## 可验证的最小闭环

先实现健康检查、菜单查询和配送范围校验，再接入对话路由。每增加一个工具，都补充正常、参数缺失和外部服务异常三类测试。
