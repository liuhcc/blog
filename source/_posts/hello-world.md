这是“代码与智能的实践笔记”的第一篇文章，也作为这个项目的说明页。它由 Hexo 生成静态页面，通过 GitHub Pages 发布，目标是把零散的技术探索沉淀成可随时查阅、持续更新的笔记。

## 项目定位

这里关注两件事：把技术问题讲清楚，以及把学习过程落到可验证的实践上。当前内容主要分为三类：

- **工程实践**：开发过程中的方案取舍、问题定位和工具使用经验。
- **AI 学习**：围绕 RAG、MCP、LangChain、LangGraph 和 Agent 项目的学习笔记。
- **项目复盘**：学习计划、阶段目标、实现边界与后续改进方向。

文章以 Markdown 维护，优先记录问题背景、方案选择、关键实现、验证方式和下一步。课程类内容只发布自主整理的总结与实验结论，不转载原始课件、视频、完整源码或任何私有配置。

## 技术方案

站点选择 Hexo 的原因很直接：它基于 Node.js，生成速度快，Markdown 写作体验成熟，并且允许按需修改主题模板和样式。项目基于 Landscape 主题进行定制，保持轻量的同时补足移动端阅读和日常检索所需的能力。

站点地址配置为 GitHub Pages 的项目路径，所有页面使用相对根路径生成，确保文章、分类、标签、搜索索引和静态资源在 `/blog/` 下都能正确访问。

## 当前体验

- 首页支持文章展开与收起，方便快速浏览摘要。
- 文章页提供目录、高亮定位、阅读进度和返回顶部，长文阅读更顺畅。
- 内置深色模式，并适配桌面和移动端布局。
- 顶部搜索基于站内 `search.json` 索引，不依赖第三方服务；支持标题与正文检索、关键词高亮、Esc 关闭以及方向键选择结果。
- 分类、标签、归档、RSS、站点地图、robots 和 404 页面均已生成，便于阅读与检索。

## 发布方式

源码在 `source` 分支维护。每次推送到该分支后，GitHub Actions 会使用 Node.js 20 安装锁定依赖、执行 Hexo 静态生成，并将生成结果发布到 `main` 分支，由 GitHub Pages 对外提供访问。

这种方式把写作、构建与上线分开：日常只需维护 Markdown 和主题代码，线上页面由自动化流程统一生成，避免手工上传静态文件带来的遗漏。

## 接下来的维护原则

1. 每篇文章保持明确主题，补充可复现的代码、命令或检查清单。
2. 涉及服务地址、账号、密钥、个人信息和课程原始资料时，先脱敏再发布。
3. 先在本地验证链接、搜索和移动端阅读，再推送触发线上构建。
4. 持续围绕大模型应用的工程化能力更新内容，包括检索、工具调用、工作流、评测与交付。

博客已经上线，后续的每一次学习和实践，都会在这里留下可回顾、可检索的记录。
