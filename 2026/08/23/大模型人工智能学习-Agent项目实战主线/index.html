从组件到项目

Agent 项目不是把模型接到聊天框就结束，而是将模型、工具、知识库、状态和业务约束组合成可靠的工作流。课程中的点餐和问数项目分别代表“多工具业务助手”和“受控数据问答”两类典型场景。

必要能力

  • RAG：为模型提供可追溯的领域知识，并通过召回、重排和引用减少无依据回答。
  • MCP 与工具调用：把业务操作封装为参数明确、权限可控的工具，不让模型直接执行高风险动作。
  • LangGraph：用状态图表达路由、重试、检查点和人工确认，替代不可控的线性提示词流程。
  • FastAPI 与数据层：提供稳定的服务接口，管理会话、业务数据和调用边界。
  • 评测与观测：记录输入、检索结果、工具调用、耗时与失败原因，建立正常、边界和失败用例。

两类项目的关键约束

点餐类 Agent 的重点是工具选择、参数确认和订单状态；问数类 Agent 的重点是数据权限、SQL 白名单、查询限额和结果解释。两者都需要在执行工具前完成参数校验，并把外部副作用放在可确认、可审计的步骤之后。

交付标准

每个项目至少应提供：清晰的 README、环境变量示例、最小演示数据、接口测试、错误处理、日志与 Docker 启动方式。完成这些基础项后，再扩展认证、持久化记忆、前端界面和自动化评测。
